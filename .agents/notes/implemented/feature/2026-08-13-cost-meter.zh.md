# Agent Note: 会话平面的美元成本台账

Status: implemented

[English](2026-08-13-cost-meter.md) | 中文

## 问题

token-meter 只数 token。混合部署（付费云编排器、订阅网关、免费本地 worker）没有按会话的美元数字，也没有上限：在账单页开口之前，花费都不可见。

## 决策

新的 `@deepseek-ai/dsh-cost-meter` 函数插件把每条持久的、模型来源的 `assistant/message` 用量事件，按来自热重载 `cost-meter` 设置 section 的价格表（提供方路由 → 模型 → 每 1M 输入/输出/缓存读/缓存写 token 的美元价）折算。该汇总不新增任何持久事件，同一日志在同一费率下得到同一成本。只读且并发安全的 `cost` 工具报告会话的美元与 token 总量；可选的 `budgetUsd` 上限让 `agent/request` 守卫在会话超支后让下一条请求响亮失败（LLM 恢复插件不会重试）。未列出的路由与未填写的费率字段按零计价。

## 备选方案

**扩展 `dsh-token-meter`。** 拒绝：它的测量只带一个无归属的用量基线与启发式表面 token；按路由计价需要每条事件的提供方/模型归属，而 meter 并不保留。

**从提供方上报的 cost 字段计价。** 拒绝：并非每个提供方都上报 cost，且计价策略属于部署而非传输。

## 后果

零持久写入、可精确重放的记账；预算守卫把超支变成按会话的响亮错误，而不是静默账单。代价：每次工具调用或受守卫请求多一次事件汇总。

## 验证

`cost-meter.spec.ts` 把两个带用量的回合按混合费率折算成精确美元数字、把未列出路由按零计价、证明预算守卫在派发前拦下下一条请求、无 agent 时工具失败，以及 schema 边界拒绝负数费率与预算。
