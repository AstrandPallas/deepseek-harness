# Agent Note: 目标治理器在子 agent 工作期间暂停空转的目标循环

Status: implemented

[English](2026-08-14-goal-governor.md) | 中文

## 问题

目标的轮次驱动在子 agent 工作时持续触发自主轮次。陷入纯对话轮次（没有工具调用）的循环白白消耗上下文与回合：它不报告进展、不启动工作，只有结算通知最终唤醒它时才结束。手动绕过——子 agent 存活期间暂停目标、结算时重新武装——在多轮波浪中反复验证有效，但这类机械策略正应由 harness 自身承担。

## 决策

新的 `@deepseek-ai/dsh-goal-governor` 宿主插件监听每个会话的回合边界与 inbox，并且只在浪费被证明之后才介入：

- **普通模式。** 每个没有工具调用的已完成回合推进空转计数；任何有产出的回合都会重置它。当计数达到 `idleRoundThreshold`（默认 3）且会话存在活跃子 agent（带有持久子标记的已附加会话）时，治理器调用目标服务的 `pause` 并进入治理模式。没有子 agent 就不介入：没有在途 agent 的空转循环被有意放过。
- **治理模式。** `subagent-settled` inbox 插入通过 `resume` 重新武装目标，让轮次驱动恰好处理一次报告。该回合结束后，只要子 agent 或未处理的结算仍在，治理器再次暂停；当都不剩、目标完成、或连续 `productiveRoundThreshold`（默认 2）个有产出回合之后，退出到普通模式。
- 治理器自身不写任何内容：每次暂停与恢复都是目标服务提交的持久 `goal/change`，因此重放保持一致。

## 备选方案

**只要子 agent 存活就总是暂停。** 拒绝：以有产出回合管理波浪的循环（重新规划、启动之间的工具工作）会被打断，让治理器变成新的摩擦而不是浪费守卫。

**按上下文增长计数而非回合。** 拒绝：token 增长是滞后的代理指标，且随模型冗长度变化；工具活动计数是“这一轮什么都没做”的直接信号。

## 后果

空转的多 agent 波浪不再消耗回合与上下文；结算处理仍按每次报告运行一次，替换启动发生在同一个武装窗口内。想要更灵敏或更慢退出的部署可以调整这两个阈值；默认值让治理器保持不碍事。

## 验证

`goal-governor.spec.ts` 针对目标替身与脚本化回合固定了六种行为：有产出回合绝不暂停、没有子 agent 的空转回合绝不暂停、有活跃子 agent 时的阈值介入、结算重新武装与再次暂停、持续有产出后的退出、目标完成时的退出。
